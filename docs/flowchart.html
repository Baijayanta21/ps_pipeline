01 End-to-end — the three passes

The estimator is a ratio, so the data pass alone is not enough. Three passes run through the same four stages; the UAPS pass additionally produces the binning information all three need, and the noise pass repeats to give a covariance.

The dashed edges are the coupling that is easy to miss. bin_info.npz is produced by the UAPS pass but consumed by all three, and ml divides both the data and the noise correlations. Change a gridding parameter and every downstream product must be regenerated together — nothing in the code checks this for you.

02 Simulation call graph

Entry point is sim_vis; everything below allskysim branches on skysimtype. Nodes marked ⚠ read parameters out of builtins rather than taking them as arguments, which is why the leaf functions cannot be called standalone.

03 Power-spectrum estimation chain

Linear, and each step's shape follows from the previous one. Both covi and dpkn come from the noise pass, which is why the noise realisations have to exist before any of this runs.
